# Komga 功能界面测试（macOS，供 Computer Use 执行）

## 1. 目的

在真实编译的 JHenTai macOS 应用里，连接真实 Komga 服务器，逐项操作界面，确认 Komga 相关功能可用。每项记录"通过 / 失败"，失败时附截图、操作步骤和实际现象。

## 2. 环境

### 2.1 被测应用

- 路径：`dist/komga-test/JHenTai Komga 测试.app`（仓库根目录下）。
- 启动：`open "dist/komga-test/JHenTai Komga 测试.app"`。
- 这个版本使用独立的应用标识 `top.jtmonster.jhentai.komgatest`，数据目录为 `~/Library/Containers/top.jtmonster.jhentai.komgatest/`。它与日常使用的 JHenTai 互不影响，且默认不开启云同步。**不要在其中开启云同步。**

### 2.2 连接信息

读取 `test/e2e/komga_e2e.json` 中的 `realServer`：

- `serverUrl`：Komga 服务器地址；
- `apiKey`：API 密钥；
- `writableSeriesTitle`：允许写操作的测试系列（下称"测试系列"）。

不要把这些值写进任何会提交的文件或报告截图之外的地方。

### 2.3 用接口查看服务器状态

需要核对服务器上的实际数据时，用以下请求（`$URL`、`$KEY` 取自上面的配置）：

```bash
# 测试系列（把标题换成 writableSeriesTitle）
curl -s -H "X-API-Key: $KEY" -H 'Content-Type: application/json' \
  -X POST "$URL/api/v1/series/list" -d '{"fullTextSearch":"<测试系列标题>"}'

# 某系列的书，按卷号排序（readProgress 为空表示未读）
curl -s -H "X-API-Key: $KEY" -H 'Content-Type: application/json' \
  -X POST "$URL/api/v1/books/list?size=100&sort=metadata.numberSort,asc" \
  -d '{"condition":{"seriesId":{"operator":"is","value":"<系列 id>"}}}'

# 单本书（含 readProgress.page / completed）
curl -s -H "X-API-Key: $KEY" "$URL/api/v1/books/<书 id>"
```

## 3. 数据约束（必须遵守）

- 会改动服务器的操作只能对**测试系列**进行：打开阅读器、标记已读/未读、下载。其他系列只浏览，不要打开阅读器（打开即会写入阅读进度）。
- 开始前用 2.3 的请求记录测试系列每一卷的 `readProgress`。当前预期为全部未读。
- 结束后恢复测试系列：若开始时全部未读，执行
  `curl -s -H "X-API-Key: $KEY" -X DELETE "$URL/api/v1/series/<系列 id>/read-progress"`，再用 2.3 确认每卷 `readProgress` 为空；若开始时有进度，逐本恢复为记录的页码。
- 不要执行"下载整个系列"（测试系列每卷约 30 MB）。单本下载在测试结束前删除。

## 4. 准备

1. 启动被测应用。首次启动停在 JHenTai 主界面。
2. 打开左侧抽屉（或阅读源切换），进入 **Komga**。显示"配置 Komga 服务器后即可浏览其中的漫画"。
3. 点"配置 Komga"，填写服务器地址与 API 密钥（用户名、密码留空），保存。
4. 回到 Komga 页面，应进入首页。

## 5. 测试项

### 5.1 首页

1. 首页依次可见：继续阅读、待读、最近新增的系列、最近更新的系列（服务器上没有内容的分区不显示）、书库列表、"已下载"入口。
2. 封面图片能加载出来。
3. 分区可以横向滚动。

预期：分区内容与服务器一致（可用 `/api/v1/books/ondeck`、`/api/v1/series/new` 抽查）。

### 5.2 书库浏览

1. 点书库进入，默认显示系列卡片。
2. 一直向下滚动：列表持续加载，最后底部显示"已全部加载"。加载的系列总数与服务器一致（`/api/v1/series/list` 的 `totalElements`）。
3. 切换"系列 / 全部书籍"。
4. 排序：添加时间、最近阅读、标题，切换升序/降序；列表顺序随之变化。
5. 显示方式：卡片、列表、详细信息三种都能正常显示。
6. 阅读状态筛选：全部、未读、阅读中、已读、新添加。抽查"阅读中"的结果与服务器一致。
7. 退出应用再进入书库，上次选择的视图、排序、筛选仍保留。

### 5.3 筛选面板

1. 在书库中点筛选按钮（滑块图标）。
2. 面板只显示服务器上有值的类别：预期有"作者""出版社""语言"；服务器没有标签和类型时，这两类不出现。
3. 选一个出版社，应用。结果中的系列都属于该出版社（打开一两个系列核对头部的出版社）。
4. 已选条件以标签显示在工具栏下方，点叉可移除，列表随之更新。
5. 切到"全部书籍"后打开筛选面板，只出现"作者"（和"标签"，若有）。

### 5.4 搜索

1. 点顶栏搜索图标，输入测试系列的部分标题，回车。
2. 标题显示"搜索：…"，结果中有测试系列。
3. 用简体写法搜索繁体标题（或反之），记录是否能搜到（Komga 服务端行为，仅记录）。

### 5.5 系列详情

1. 打开测试系列。头部显示：封面、标题、"共 N 本 · 已读 … · 阅读中 … · 未读 …"（与服务器一致）、阅读方向（测试系列为"从右到左"）、作者与出版社标签。
2. 卷按卷号从小到大排列。
3. 点作者标签：进入"作者"筛选结果，含测试系列。返回，回到系列页且滚动位置不变。
4. 点出版社标签：同上。
5. 把系列内排序改为降序，返回再进入该系列，仍为降序；书库列表的排序不受影响。改回升序。

### 5.6 继续阅读与阅读器

1. 测试系列全部未读时，"继续阅读"按钮显示第 1 卷。点击，阅读器打开第 1 卷。
2. 阅读方向应为从右到左（向左滑翻到下一页）。
3. 翻 3～4 页，退出阅读器。
4. 系列页中第 1 卷显示"继续阅读 · x/N"；用 2.3 查看服务器上第 1 卷的 `readProgress.page` 与 x 一致。
5. 再次点"继续阅读"，从刚才的页码继续。
6. 打开阅读器底部缩略图条，缩略图能正常显示。

### 5.7 读完与下一本

1. 在阅读器中拖动进度条到最后一页。
2. 屏幕下方出现"下一本"按钮；顶部菜单有"上一本 / 下一本"图标。
3. 点"下一本"：打开第 2 卷。
4. 退出后，第 1 卷显示"已读完"；服务器上第 1 卷 `completed=true`。
5. 在第 2 卷用顶部"上一本"回到第 1 卷。

### 5.8 别处修改的进度

1. 用接口把第 3 卷进度设为第 10 页：
   `curl -s -H "X-API-Key: $KEY" -H 'Content-Type: application/json' -X PATCH "$URL/api/v1/books/<第3卷 id>/read-progress" -d '{"page":10}'`
2. 在应用里下拉刷新系列页，第 3 卷显示"继续阅读 · 10/N"。
3. 打开第 3 卷，从第 10 页开始；服务器上仍是第 10 页（没有被改回第 1 页）。

### 5.9 标记已读 / 未读

1. 长按第 4 卷 → 标记为已读：状态变为已读，服务器 `completed=true`。
2. 长按第 4 卷 → 标记为未读：状态变为未读，服务器 `readProgress` 为空。
3. 系列头部菜单（⋮）→ 整个系列标记为已读：所有卷变为已读，头部计数更新。
4. 再选"整个系列标记为未读"：所有卷变为未读，服务器全部为空；之后下拉刷新，不应有任何卷恢复成阅读中（旧进度不会被推回）。

### 5.10 离线下载

1. 长按第 5 卷 → 下载。封面右下角出现进度，完成后变为"已下载"图标。
2. 首页"已下载"条目计数为 1，进入后能看到第 5 卷。
3. 断开与 Komga 的网络（例如关闭 Wi‑Fi 或断开 Tailscale）。
4. 在"已下载"中打开第 5 卷：页面正常显示，翻几页后退出。
5. 恢复网络，回到 Komga 页面下拉刷新。服务器上第 5 卷的进度应与离线时读到的页码一致（补发成功）。
6. 长按第 5 卷 → 删除下载，"已下载"计数归零。

### 5.11 全量同步按钮

点顶栏"与 Komga 同步阅读进度"图标，提示"已同步 N 本书的进度"或"阅读进度已是最新"。

### 5.12 错误提示

1. 在 Komga 设置中把 API 密钥改成错误值并保存。
2. 首页提示"API 密钥被拒绝……可改用用户名和密码"。
3. 改回正确的 API 密钥并保存，首页恢复正常。

### 5.13 导航

1. 首页 → 书库 → 系列 → 筛选结果，逐级点返回（左上角返回键、macOS 返回手势或 Esc 均可），每级都恢复原样。
2. 打开左侧抽屉选择 EH 的某个页面，能切回 JHenTai 主界面。

## 6. 收尾

1. 按第 3 节恢复测试系列的阅读进度，并用 2.3 确认。
2. 确认"已下载"为空。
3. 退出被测应用。可选：删除 `~/Library/Containers/top.jtmonster.jhentai.komgatest/`。

## 7. 报告格式

- 每个测试项一行：编号、通过/失败、备注。
- 失败项：截图、复现步骤、预期与实际现象。
- 末尾列出对服务器做过的全部写操作，以及恢复后的核对结果。
