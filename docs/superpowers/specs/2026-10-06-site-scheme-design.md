# 站点方案切换设计

## 1. 目标

侧边栏顶部（原 E-Hentai 账号区域）改为方案头：一个下拉菜单选择方案（E-Hentai、nhentai、wnacg、JM、Komga、PDF），选择后整个应用切换到该方案的页面；同一区域显示该方案的账号并可登录、登出。搜索页内单独切换站点的功能保留。

## 2. 方案与导航

方案保存在新的设置 `SchemeSetting`（本机，不参与云同步）中，只保存站点方案（E-Hentai、nhentai、wnacg、JM）；Komga 与 PDF 仍是覆盖整个界面的独立页面，进入时不改变保存的站点方案，选回站点方案时回到主界面。

| 方案 | 导航项 |
| --- | --- |
| E-Hentai | 首页、搜索、热门、排行榜、收藏、关注、历史、下载、设置（与现在相同） |
| nhentai | 首页（最新）、搜索、热门（本周热门）、收藏、历史、下载、设置 |
| wnacg | 首页（最新）、搜索、收藏、历史、下载、设置 |
| JM | 首页（推荐）、分类、排行、每周必看、搜索、收藏、历史、下载、设置 |

- 历史与下载不区分来源，各方案共用。
- 收藏页沿用现有的来源切换：切换方案时收藏页切到该方案的来源，菜单仍可手动切换。
- 新打开的搜索页默认使用当前方案的站点，搜索页内的站点切换不变。
- 原抽屉底部的「阅读来源」切换与桌面侧栏最后一项并入方案下拉菜单。
- 桌面布局没有账号区域，侧栏顶部增加方案按钮，菜单中包含方案与当前方案的账号操作。

## 3. JM 页面

接口均已用只读请求核实（2026-10-06）。

- **推荐**：`/promote` 的栏目以横向封面行展示，顶部为 `/hot_tags` 热门标签（点击按 JM 搜索）。「更多」：`promote` 类栏目用 `/promote_list?id=&page=`（页码从 0 开始，每页 27 本，按 `total` 判断末页）；`category_id` 类按其分类用 `/categories/filter` 浏览；与分类同名的 `not_in_category_id` 栏目（禁漫漢化組）同样按分类浏览；`library`、`novels`（书库、小说）不显示。
- **分类**：`/categories` 的分类（「最新A漫」对应全部）与排序（最新 `mr`、观看 `mv`、喜欢 `tf`、图片数 `mp`），用 `/categories/filter?c=&o=` 浏览。移动端接口不支持副分类。
- **排行**：时间段（今日、本周、本月、全部）× 排序（观看、喜欢）× 分类，`o = {排序}_{t|w|m}`，全部时为 `{排序}`。排行榜有数量上限（实测本周观看 64 本）。
- **每周必看**：`/week` 的期数（下拉选择，默认最新）与类型（韓漫、日漫、其他），`/week/filter?id=&category=` 只有一页。

## 4. 实现要点

- 布局逻辑（移动、桌面）监听方案变化，重建导航项并回到该方案的首页；页面逻辑仍按类型或标签注册为常驻实例，切换方案不会丢失其他方案已加载的列表。
- nhentai、wnacg 的首页和 nhentai 的热门复用现有的站点分发（搜索配置带站点标记、关键词为空），不新增请求方式。
- JM 列表页的逻辑覆盖 `getGalleryPage`，直接调用 `JmSource`；分类列表、每周期数、热门标签在本次运行内缓存。
- `TabBarIconNameEnum` 只在末尾追加新值，已保存的默认标签序号不变。

## 5. 测试

- 端到端：真实 JM 接口验证推荐栏目、栏目「更多」分页、分类浏览、排行、每周必看、热门标签。
- 界面：驱动方案头切换方案，断言导航项变化、收藏页来源随之切换、账号行显示对应站点。
