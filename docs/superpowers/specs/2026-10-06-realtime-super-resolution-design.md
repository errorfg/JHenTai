# 在线阅读时的实时超分设计（实验）

日期：2026-10-06
状态：实验版，仅桌面端（macOS、Windows、Linux），未发版

## 1. 背景与目标

现有的超分只能对已下载的画廊预先处理。目标是在线阅读时直接看到超分后的页面：每页下载完即在后台超分，完成后替换原图，不需要先下载整本。

可行性依据（M4 Max，800×1138 的页面，每页启动一次程序）：realesr-animevideov3 2 倍约 0.36 秒，realcugan 2 倍约 0.55 秒；阅读速度约每页 3–6 秒。模型与倍数由用户自行选择，基准测试用于在各台机器上取得数据。

## 2. 组成

| 部分 | 位置 | 说明 |
|---|---|---|
| 程序与模型清单、运行 | `lib/src/service/sr/sr_tools.dart` | `SrEngine`（realesrgan、realcugan 的 ncnn-vulkan 命令行程序及其发布包）、`SrModel`、`SrConfig`（模型 + 倍数 + 降噪）、`SrRunner`（不经 shell 启动，工作目录为程序所在目录） |
| 输入准备 | `sr_input.dart` | 解码任意格式、还原 JM 条带、编码为不带透明通道的 PNG；动图与宽度达到上限的页面不处理 |
| 实时服务 | `realtime_sr_service.dart` | 队列（一次运行处理一批，阅读位置之后最近的页面优先）、内存中的结果（上限 512 MB，最久未用的先出）、程序安装 |
| 基准测试 | `sr_benchmark.dart`、设置页的对话框 | 见第 5 节 |
| 阅读器 | `read_page_logic.dart`、`base_layout.dart` | 原图显示后请求超分；结果解码后替换；顶部菜单开关 |

与原有的"已下载画廊超分"（`super_resolution_service.dart`）互不影响，只共用 GPU 编号设置。

## 3. 输入为何统一转成 PNG

- 图片缓存文件没有扩展名，程序按扩展名选择解码器；JM 页面还需先还原条带。
- PNG 不能带透明通道：程序遇到透明通道会一并放大并强制输出 PNG，忽略指定的输出格式。因此从 RGBA 像素自行编码 RGB PNG（透明处按白底），压缩级别取最低，文件用后即删。
- 两个程序在 macOS 上不支持 BMP（解码失败），所以不用无压缩的 BMP。

## 4. 批量与阅读器中的流程

### 4.1 为什么按批运行

RTX 5090（Windows）上的基准测试：逐页各启动一次程序时每页约 0.9–1.1 秒，各模型、各倍数几乎相同；9 页一次运行共约 1.15 秒。即每次启动的固定开销约 0.85 秒，每页实际计算约 0.03–0.08 秒（M4 Max 上分别约 0.22 秒与 0.13–0.36 秒）。所以一次运行处理一批页面：每批最多 `realtimeBatchSize` 页（默认 4，可选 1、2、4、8、16）。

### 4.2 一批的输入与输出

1. 取等待中距阅读位置最近的页面，最多一批；同一事件循环内提出的请求都算在等待中（开始运行前让出一轮）。
2. 并行取得各页的原图并准备输入；不处理的页面（动图、宽图、读取失败）不参与。
3. 在临时目录新建本次运行的文件夹，各页写为 `in/<批内序号>.png`，程序以文件夹方式运行一次，结果为 `out/<批内序号>.jpg`。按同一序号取回，页面之间不会错位。
4. 结果读入内存后，整个文件夹立即删除。程序只能读写文件，这一步无法省去；磁盘上不保留任何超分结果。
5. 结果（编码后的 JPEG）留在内存，按「模型|倍数|降噪|页面地址」索引，总量超过 512 MB 时移除最久未用的；被移除的页面再次显示时先显示原图并重新超分。

### 4.3 阅读器

- 提前量：打开实时超分后，阅读器按批量的整数倍提前取页并超分。目标位置为「当前页 + 1 + max(预载页数设置, 批量)」向上取整到批量的整数倍；阅读位置前进时，新的页面在越过整数倍边界时整批提出，而不是每翻一页提出一页。未建好的页面由阅读器主动解析地址并下载原图（进入图片缓存，之后显示时直接使用）。
- 显示：页面构建时查内存中的结果，有则直接以内存图片显示（`EHImage.memory`），否则显示原图；结果就绪并解码（`precacheImage`）后刷新该页。提前处理好的页面首次显示就是超分后的图。
- 提前量之外的页面（跳转到达）在原图显示完成时提出请求。
- 关闭阅读器时清空等待中的页面，正在运行的一批做完；开关关闭时页面回到原图。

设置项（`SuperResolutionSetting`）：开关、模型、倍数、降噪等级、每批页数、不处理的最小宽度（默认 1600，0 为不限）。程序目录：应用可执行文件旁有 `sr_tools` 文件夹时用它（实验包自带，免下载），否则为应用数据目录下的 `sr_tools`，可在设置页下载安装。

## 5. 基准测试

设置页「超分辨率 → 基准测试」。输入为页面图片所在的文件夹，或一个 JM 章节号：

- 文件夹：直接读取其中的图片，不联网。可执行文件旁有 `sr-benchmark-pages` 文件夹时默认填入。
- JM 章节：页面在开始时各下载一次，存入本次测试的文件夹，此后所有配置都读本地文件。

对每个配置（全部模型 × 倍数 × 降噪，共 21 个）：逐页各启动一次程序计时（与阅读时相同），再把全部页面放在一次运行里计时；后者的输出保留在 `out/<配置>/`，供肉眼比较。结果写入 `report.json` 与 `report.md`（系统、GPU 列表与所用编号、页面尺寸、每个配置的逐页耗时、首次运行耗时、单次运行的每页耗时、输出大小、失败原因），位于系统下载目录下的 `JHenTai-SR-Benchmark-<时间>`。

## 6. 验证

- 用真实的程序运行（`test/e2e/sr_e2e.json` 指定程序目录，缺省则跳过）：各模型按倍数输出；同一页只超分一次，之后取自内存；JM 页面先还原；宽图与动图不处理；十页不同颜色的页面乱序提出，按阅读位置每批四页处理，每页得到自己的结果；每次运行后磁盘上没有文件；基准测试产出报告并保留输出。
- 阅读器端到端：打开在线会话，五页按「四页 + 一页」两批提前超分，页面变为 2 倍的图，磁盘上没有文件；关闭开关后回到原图。
- 在线：真实 JM 章节的基准测试；从发布地址下载、解压并运行两个程序。
- Windows：基准测试（逐页与文件夹两种运行方式）在 RTX 5090 上 21 个配置全部成功；实时超分在 Windows 上尚未经用户验证。Linux 未运行过；macOS 应用（沙盒）内启动下载的程序未验证。
